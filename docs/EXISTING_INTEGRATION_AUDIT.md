## Current end-to-end ownership and event flow

```text
Auth principal → ChatService/session store → capability/tool or ProviderGateway
               → existing event fabric → RuntimeEventService → authenticated SSE
               → frontend runtime projection → presentation planner/envelope → React renderer
```

Conversation persistence, provider execution, capability authorization and audit remain owned by their existing backend services. The runtime protocol is a projection/transport for their real activity; presentation metadata cannot authorize execution.

## Integration changes made in this audit

- Added an authenticated endpoint gateway that persists endpoint identity, reported renderer capabilities, active session attachment and last-seen connectivity in the existing SQL-backed key/value store. Endpoint registration restores the most recent owned conversation (or creates the first one) before negotiation, so entering the authenticated shell starts JARVIS directly.
- Reused the existing renderer negotiation and runtime event systems: endpoint capability reports remain descriptive, session ownership is checked by `ChatService`, and endpoint discovery/disconnect are projected as canonical device events.
- The legacy buffered and streaming chat endpoints pass the middleware request ID into `ChatService`; request ID is returned in chat responses and stream errors/metadata.
- Buffered and streaming provider calls run with the same canonical request ID in the existing observability context. Chat idempotent replay preserves the persisted request ID.
- Capability execution IDs are now shared by the orchestrator event and canonical capability event. Chat no longer emits duplicate manual started/completed events alongside the orchestrator's real execution events; unavailable capability is still reported truthfully.
- Image-generation completion is emitted only after artifact persistence and now distinguishes failed generation from completion without including prompt contents.
- Synthetic legacy `"typing"` SSE output was removed. A request may enter `WAITING`; the UI should only enter active work states after real backend lifecycle events.

## Ordered remaining integration work

1. Add successful authenticated SSE HTTP tests for snapshot, sequence replay, and disconnect/reconnect; define durable/shared journal behavior before multi-worker deployment.
2. Expand producer coverage from verified source contracts: provider selected/started, all actual voice lifecycle names, image artifact results, browser evidence, and task/job lifecycle. Keep event payloads allowlisted and sensitivity-classified.
3. Make the SSE projection the single frontend runtime activity authority; remove or clearly demote ACK-only WebSocket and dashboard polling paths where they duplicate runtime truth.
4. Implement real semantic renderers and register only those the client can actually display. Keep location, vision, voice listening, video and scheduler paths explicitly unavailable until real configured vertical tests exist.
5. Propagate canonical request IDs through non-chat interaction entry points and align runtime IDs with audit/trace lookup without persisting private content.
